# 记忆系统问题修复计划

## 问题分析

### 问题一：记忆评分显示为 N/A

**现象**：昨天添加的记忆信息，今天在记忆面板里看评分变成了 N/A

**根本原因**：
1. 在 `MemoryList.tsx` 第 350 行，显示评分使用 `{memory.score?.toFixed(2) ?? 'N/A'}`
2. 旧记忆可能是在数据库迁移前创建的，`score` 字段可能为 `null` 或未正确初始化
3. 在 `storage.rs` 第 99 行的迁移逻辑中，虽然添加了 `score` 列并设置了默认值 `0.5`，但可能存在边界情况

**需要检查**：
- 数据库中旧记忆的 `score` 字段是否正确
- 前端获取记忆时 `score` 字段是否正确传递

---

### 问题二：记忆提取跳过候选记忆阶段

**现象**：首次发送图片对话时，记忆直接被添加到记忆列表，跳过了候选记忆阶段

**根本原因**：

当前代码存在两套记忆提取流程：

1. **新流程** (`newExtractionPipeline`) - [MemoryExtractionService.ts:134-167](file:///c:/Users/Misaki/Desktop/git/nexus-ai-assistant/src/agent/memory/MemoryExtractionService.ts#L134-L167)
   - 直接调用 `this.store.storeCandidates()` 
   - 将记忆直接存入正式记忆列表
   - **跳过了候选记忆阶段**

2. **旧流程** (`legacyExtractionPipeline`) - [MemoryExtractionService.ts:169-208](file:///c:/Users/Misaki/Desktop/git/nexus-ai-assistant/src/agent/memory/MemoryExtractionService.ts#L169-L208)
   - 调用 `TauriMemoryClient.addCandidateMemory()`
   - 将记忆添加到候选记忆表
   - 需要用户审核后才进入正式记忆列表

当前 `triggerExtraction` 方法调用的是 `newExtractionPipeline`，导致候选记忆流程被完全绕过。

**用户期望的正确流程**：
```
用户消息 → AI回复 → 触发记忆提取 → 候选记忆列表 → 用户审核 → 正式记忆列表
```

**当前实际流程**：
```
用户消息 → AI回复 → 触发记忆提取 → 直接存入正式记忆列表
```

---

## 修复方案

### 方案一：修复评分 N/A 问题

**修改文件**：`src-tauri/src/memory/storage.rs`

1. 在 `get_all_memories` 方法中，确保 `score` 字段正确读取
2. 添加防御性代码：如果 `score` 为 `null` 或 `0`，使用 `importance` 作为默认值

**修改文件**：`src/components/MemoryPanel/MemoryList.tsx`

1. 在显示评分时，如果 `score` 为 `N/A`，显示 `importance` 作为备用值

---

### 方案二：恢复候选记忆流程

有两种修复思路：

#### 思路 A：修改新流程，先存入候选记忆

修改 `newExtractionPipeline` 方法：
1. 不直接调用 `store.storeCandidates()`
2. 改为调用 `TauriMemoryClient.addCandidateMemory()` 将记忆存入候选记忆表
2. 用户在候选记忆面板审核后，再调用 `acceptCandidate` 将记忆存入正式列表

**优点**：符合用户期望的流程
**缺点**：需要用户手动审核每条记忆

#### 思路 B：添加配置选项，让用户选择流程

1. 添加配置项 `autoAcceptMemories`（自动接受记忆）
2. 如果 `autoAcceptMemories = true`：使用当前新流程，直接存入正式列表
3. 如果 `autoAcceptMemories = false`：使用候选记忆流程，需要用户审核

**优点**：灵活性高，用户可以选择
**缺点**：增加配置复杂度

#### 推荐方案：思路 A + 优化

考虑到用户体验，推荐以下方案：

1. **默认使用候选记忆流程**：所有提取的记忆先进入候选记忆表
2. **批量操作支持**：用户可以一键接受所有候选记忆
3. **智能过滤**：对于高置信度（importance > 0.9）的记忆，可以自动接受（可选配置）
