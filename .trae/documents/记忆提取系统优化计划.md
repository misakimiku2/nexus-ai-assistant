# 记忆提取系统优化计划

## 问题诊断

通过分析 10 轮对话日志，发现以下核心问题：

### 问题 1：sourceText 来源混乱（最严重）

**现象**：模型经常从 AI 回复中提取 sourceText，而不是用户原话。

**日志证据**：
```
span: 现在的BMI是23.5(正常范围)
source: 你现在的BMI是23.5(正常范围),减到70公斤是23.1,非常健康！...
```
这是 AI 的回复，不是用户原话！

```
span: 汤圆是公猫
source: 2岁的英短蓝猫正是最粘人的年纪,每天蹭你半小时...
```
span 是用户说的话，但 sourceText 是 AI 的回复。

**根本原因**：`PreFilterService.formatForExtraction` 把 AI 回复也传给了记忆提取模型。

### 问题 2：候选记忆质量差

**最终进入候选记忆的内容**：
| 内容 | 问题 |
|------|------|
| `你有遇到这种困扰吗？` | 这是问题，不是事实 |
| `2岁的英短蓝猫正是最粘人的年纪，每天蹭你半小时` | 这是 AI 的话，不是用户原话 |
| `来上海这一年，工作充实、有猫、有爱好...` | 这是 AI 的总结 |
| `你有没有什么特别喜欢的导演或者电影？` | 这是问题 |

### 问题 3：被错误过滤的好记忆

```
span: 其实我有个秘密没跟别人说过——我来上海,某种程度上是因为一段感情.
source: 用户: 我来上海,某种程度上是因为一段感情.前任是成都人...
```
被拒绝原因：标点符号不匹配（破折号 `——` vs 逗号 `,`）

### 问题 4：normalizeForMatch 不完整

当前只处理了：
- `（）` → `()`
- `，` → `,`
- `。` → `.`

未处理：
- 破折号 `——`、`—`
- 顿号 `、`
- 冒号 `：`
- 分号 `；`
- 引号 `""`、`''`
- 感叹号 `！`
- 问号 `？`

### 问题 5：信号词检查过于严格

很多有效记忆因为没有强信号词被拒绝：
```
[MemoryFilter] Rejected: no valid signal
```

例如：`明年年假想去日本` - 没有"喜欢/是/有/做/用/学/看/写"，被拒绝。

## 解决方案

### 方案 1：PreFilterService 只传用户消息（最重要）

**修改文件**：`src/agent/memory/PreFilterService.ts`

**修改内容**：
- 新增配置项 `userOnly: boolean`
- `filter()` 方法默认只返回用户消息
- `formatForExtraction()` 只格式化用户消息

**预期效果**：彻底解决 sourceText 来源混乱问题

### 方案 2：完善 normalizeForMatch

**修改文件**：`src/agent/memory/MemoryFilter.ts`

**修改内容**：
```typescript
function normalizeForMatch(text: string): string {
  return text
    .replace(/（/g, "(")
    .replace(/）/g, ")")
    .replace(/，/g, ",")
    .replace(/。/g, ".")
    .replace(/：/g, ":")
    .replace(/；/g, ";")
    .replace(/！/g, "!")
    .replace(/？/g, "?")
    .replace(/[""]/g, '"')
    .replace(/['']/g, "'")
    .replace(/[———]/g, "-")
    .replace(/、/g, ",")
    .replace(/\s+/g, " ")
    .trim();
}
```

### 方案 3：放宽信号词检查

**修改文件**：`src/agent/memory/MemoryFilter.ts`

**修改内容**：
1. 扩展 STRONG_SIGNALS：
```typescript
const STRONG_SIGNALS = [
  "喜欢", "是", "有", "做", "用", "学", "看", "写",
  "想", "希望", "打算", "养", "住", "在", "去", "来"
];
```

2. 为 preference/fact 增加更多绿色通道：
- 包含地名 + 动词（如 "去日本"、"在徐汇"）
- 包含时间 + 行为（如 "明年年假"、"周末"）

### 方案 4：改进 Prompt

**修改文件**：`src/agent/memory/MemoryModelClient.ts`

**修改内容**：
在 Prompt 中明确强调：
```
【重要规则】
1. sourceText 必须是"用户:"开头的消息
2. 不要从"助手:"的消息中提取记忆
3. span 必须是用户原话的连续子串
```

### 方案 5：增加 sourceText 来源验证

**修改文件**：`src/agent/memory/MemoryFilter.ts`

**新增验证**：
```typescript
function sourceTextValidation(m: FilterInput): boolean {
  // sourceText 必须以"用户:"开头或来自用户消息
  if (m.sourceText.startsWith('助手:') || m.sourceText.startsWith('AI:')) {
    console.warn('[MemoryFilter] Rejected: sourceText from AI response');
    return false;
  }
  return true;
}
```

## 风险评估

1. **只传用户消息**：可能丢失用户在对话中确认的信息（如 "对，我是程序员"）
   - 解决：这是可接受的，因为用户确认的信息通常已经在之前的消息中说过

2. **放宽信号词**：可能引入更多噪音
   - 解决：保持其他过滤规则的严格性

3. **标点符号统一**：可能误匹配
   - 解决：边界约束检查仍然有效
