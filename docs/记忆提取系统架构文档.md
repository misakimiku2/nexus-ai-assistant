# 记忆提取系统架构文档

## 概述

记忆提取系统是 Nexus AI Assistant 的核心组件，负责从对话中自动提取、去重、存储和检索用户相关的记忆信息。系统采用**规则 + 语义驱动**的架构，支持双模型配置（专用记忆提取模型 + 主对话模型），并具备完整的兜底策略。

### 1. MemoryExtractionService (主控制器)

**文件**: `src/agent/memory/MemoryExtractionService.ts`

**职责**: 协调整个记忆提取流程，管理状态和触发条件

```typescript
  // 触发提取
}
```

**模型选择策略**:
```typescript
setMemoryModelConfig(config: MemoryModelConfig): void {
  if (config.enabled) {
    // 使用专用记忆提取模型 (如 Qwen2.5-3B)
    this.useMainModel = false;
    this.modelClient.updateConfig(config);

    // 兜底：使用主对话模型
    this.useMainModel = true;

  }
}
```

### 3. MemoryModelClient (LLM 提取层)

**文件**: `src/agent/memory/MemoryModelClient.ts`

**职责**: 调用 LLM 提取记忆，解析输出

**输出格式**:
```
[类型] 内容 | 重要性
```

**示例**:
```
[identity] 用户是一名产品经理，28岁 | 0.9
[preference] 用户喜欢摄影，尤其是风景和人文纪实 | 0.85
[fact] 用户刚从北京搬到杭州工作 | 0.9
[constraint] 用户对猫毛过敏 | 0.8
```

**Prompt 严格规则**:

```
1. 只提取用户明确说出的信息，不要推断、猜测或编造
2. 不要提取 AI 的任务或计划（如"帮助用户..."、"为用户推荐..."）
3. 不要添加对话中没有的细节（如用户没说年龄，就不能写年龄）
4. 每条记忆必须来自用户的原话
5. 内容要具体，不要模糊的描述
6. 总共不超过 8 行
7. 如果没有重要信息，输出空行
```

**禁止输出**:

```
- AI 的任务或计划（如"帮助用户适应新城市"）
- 推断的信息（如用户没说养猫，就不能写"养了一只猫"）
- 编造的细节（如用户没说年龄，就不能写"28岁"）
- 模糊的描述（如"用户有一些爱好"）
- 重复的信息
- 对话中没有提到的具体细节
```

**特别注意**:

```
- 用户说"想学习"不等于"擅长"，应该用 task 或 preference 类型
- 用户说"感兴趣"不等于"擅长"，应该用 preference 类型
- 只有用户明确说"我会"、"我擅长"才能用 skill 类型
```

**MultiPassParser (三轮解析策略)**:

| Pass | 策略 | 正则 | 说明 |
|------|------|------|------|
| Pass 1 | 严格匹配 | `^\[(type)\]\s*(.+?)\s*\|\s*(0\.[7-9]\d*\|1\.0)\s*$` | 完整格式匹配 |
| Pass 2 | 宽松匹配 | 容忍格式偏差 | 处理轻微格式问题 |
| Pass 3 | 关键词提取 | 检测关键词 | 兜底策略 |

**SafeExtract (安全验证层)**:

```typescript
// 验证规则
- 类型白名单: identity, fact, preference, task, constraint, skill
- 内容长度: 6-200 字符 (重要短信息可低于6字符)
- 重要性范围: 0.7-1.0
- 垃圾字符检测: 重复字符、纯符号
- 完全字符串去重
- AI 任务过滤: 检测"帮助用户"、"希望得到"等 AI 任务模式
- 模糊描述过滤: 检测"一些"、"某些"等模糊词汇

// 重要短信息白名单
- 用户名字: /^用户[叫是].+$/
- 用户性别: /^用户[男女]$/
- 用户年龄: /^\d+岁$/
```

### 6. MemoryScoreCalculator (评分层)

**文件**: `src/agent/memory/MemoryScoreCalculator.ts`

**职责**: 计算记忆的综合评分，支持记忆衰减和访问奖励

**评分公式**:
```
score = importance × decay_factor + access_bonus

其中:
  decay_factor = e^(-decay × days_since_access)
  access_bonus = min(accessCount × 0.01, 0.2)
```

**评分组成**:

| 组成部分 | 计算方式 | 说明 |
|----------|----------|------|
| importance | LLM 提取时设定 | 基础重要性 (0.7-1.0) |
| decay_factor | e^(-decay × 天数) | 时间衰减因子 |
| access_bonus | min(次数×0.01, 0.2) | 访问奖励 |

**衰减率 (decay) 默认值**:

| 记忆类型 | decay 默认值 | 说明 |
|---------|-------------|------|
| identity | 0.001 | 身份信息，衰减最慢 |
| skill | 0.002 | 技能信息 |
| constraint | 0.003 | 约束信息 |
| preference | 0.005 | 偏好信息 |
| fact | 0.01 | 事实信息 |
| task | 0.02 | 任务信息，衰减最快 |

**衰减计算示例**:
```
假设: importance = 0.85, decay = 0.01, days_since_access = 7

decay_factor = e^(-0.01 × 7) = e^(-0.07) ≈ 0.932
score = 0.85 × 0.932 = 0.792
```

**清理策略**:
```typescript
// 评分低于阈值的记忆可被清理
if (score < 0.3) {
  // 标记为不活跃
  is_active = false;
  marked_inactive_at = now;
}
// 7天后仍未恢复，删除
if (is_active = false && marked_inactive_at < 7_days_ago && score < 0.1) {
  // 永久删除
}
```

### 7. 候选记忆流程

**文件**: `src/agent/memory/MemoryExtractionService.ts`

**流程图**:
```
用户消息 → AI回复 → 触发记忆提取 → 候选记忆列表 → 用户审核 → 正式记忆列表
```

**详细步骤**:

1. **触发提取**: 当满足触发条件时，`MemoryExtractionService.triggerExtraction()` 被调用

2. **生成候选记忆**: 提取的记忆首先存入 `candidate_memories` 表，状态为 `pending`

3. **用户审核**: 用户在候选记忆面板中审核每条候选记忆
   - **接受**: 调用 `acceptCandidate()`，记忆存入正式记忆列表
   - **拒绝**: 调用 `rejectCandidate()`，记忆被删除
   - **编辑**: 修改内容后再接受

4. **候选记忆数据结构**:
```typescript
interface CandidateMemory {
  id: string;
  content: string;
  memoryType: MemoryType;
  confidence: number;
  sourceSessionId: string;
  sourceMessageIds: string[];
  createdAt: number;
  status: 'pending' | 'accepted' | 'rejected';
  importance: number;
}
```

### 8. 数据库迁移与修复

**文件**: `src-tauri/src/memory/storage.rs`

**自动修复机制**:

应用启动时会自动检测并修复以下问题：

| 问题 | 修复方式 |
|------|----------|
| `score = 0` 或 `NULL` | 使用 `importance` 值填充 |
| `score > 1.0` 或 `inf` | 使用 `importance` 值填充 |
| `decay = 0` 或 `NULL` 或 `1.0` | 根据记忆类型设置默认值 |
| `last_accessed_at <= 0` | 使用当前时间戳 |
| `is_active = 0` 但 `score >= 0.3` | 恢复为活跃状态 |

**迁移日志示例**:
```
[MemoryStorage] 修复 35 条记忆的 score/decay/last_accessed_at 值...
[MemoryStorage] 修复完成
```

### 专用记忆提取模型 (推荐)

```typescript
interface MemoryModelConfig {
  enabled: true;
  provider: 'lm-studio' | 'ollama';
```

## 完整数据流

```
1. 用户发送消息
       │
       ▼
2. ReActEngine 处理对话
       │
       ▼
3. 触发记忆提取 (triggerMemoryExtraction)
       │
       ├── 检查触发条件 (消息数 ≥ 4 或 内容长度 ≥ 300)
       │
       ▼
4. MemoryExtractionService.triggerExtraction()
       │
       ├── 选择模型 (专用模型 or 主模型兜底)
       │
       ▼
5. PreFilterService.filter()
       │
       ├── 过滤短消息
       ├── 过滤工具调用
       ├── 角色过滤
       ├── 字符串去重
       └── 截取最近 N 条
       │
       ▼
6. MemoryModelClient.extractCandidates()
       │
       ├── 调用 LLM 提取记忆
       ├── MultiPassParser 解析输出
       └── SafeExtract 安全验证
       │
       ▼
7. 存入候选记忆表 (candidate_memories)
       │
       ├── 状态: pending
       └── 等待用户审核
       │
       ▼
8. 用户审核候选记忆
       │
       ├── 接受 → 进入步骤 9
       └── 拒绝 → 删除候选记忆，流程结束
       │
       ▼
9. MemoryStore.storeCandidates()
       │
       ├── 并行生成 Embedding (Promise.all)
       │
       ▼
10. SimilarityEngine.processCandidate()
       │
       ├── 搜索相似记忆 (动态 topK)
       ├── 类型过滤
       └── 计算相似度
       │
       ├──▶ 相似度 > 0.85 → SKIP + boost
       │
       ├──▶ 相似度 0.75~0.85 → MERGE
       │         │
       │         ├── 合并成功 → 更新记忆
       │         └── 合并失败 → fallback to INSERT
       │
       └──▶ 相似度 < 0.75 → INSERT
                │
                ▼
11. 计算初始评分
       │
       ├── score = importance (初始评分等于重要性)
       └── decay = 根据类型设置默认值
       │
       ▼
12. TauriMemoryClient.addMemory()
       │
       ▼
13. SQLite 数据库持久化
       │
       ▼
14. 定期演化周期 (每6小时)
       │
       ├── 衰减计算: score *= e^(-decay × days)
       ├── 淘汰低价值: score < 0.3 → 标记不活跃
       └── 清理过期: 不活跃7天 + score < 0.1 → 删除
```

## 故障排查

### 问题 1: 记忆提取不触发

**检查项**:
1. 触发条件是否满足 (消息数 ≥ 4 或 内容长度 ≥ 300)
2. 是否有正在进行的提取任务 (`isExtracting = true`)
3. 模型配置是否正确

### 问题 2: 记忆提取失败

**检查项**:
1. 模型 API 是否可访问
2. 模型名称是否正确
3. 查看控制台日志中的错误信息

### 问题 3: Embedding 生成失败

**检查项**:
1. Rust 后端是否正确加载 Embedding 模型
2. 检查 `generate_embedding` 命令是否注册
3. 查看 Rust 后端日志

### 问题 4: 记忆重复存储

**检查项**:
1. 相似度阈值是否合理
2. 类型过滤是否生效
3. Embedding 模型是否正常工作
