# 记忆提取系统架构文档

## 概述

记忆提取系统是 Nexus AI Assistant 的核心组件，负责从对话中自动提取、去重、存储和检索用户相关的记忆信息。系统采用**规则 + 语义驱动**的架构，支持双模型配置（专用记忆提取模型 + 主对话模型），并具备完整的兜底策略。

## 核心组件详解

### 1. MemoryExtractionService (主控制器)

**文件**: `src/agent/memory/MemoryExtractionService.ts`

**职责**: 协调整个记忆提取流程，管理状态和触发条件

**关键属性**:

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `MIN_NEW_MESSAGES` | number | 4 | 触发提取的最小新消息数 |
| `MIN_CONTENT_LENGTH` | number | 300 | 触发提取的最小内容长度 |
| `MAX_INPUT_MESSAGES` | number | 6 | 每次提取处理的最大消息数 |
| `lastProcessedIndex` | number | 0 | 已处理消息的游标位置 |
| `useMainModel` | boolean | false | 是否使用主模型（兜底模式） |

**触发条件**:
```typescript
// 双阈值触发机制
if (newMessages.length >= MIN_NEW_MESSAGES || newContentLength >= MIN_CONTENT_LENGTH) {
  // 触发提取
}
```

**模型选择策略**:
```typescript
setMemoryModelConfig(config: MemoryModelConfig): void {
  if (config.enabled) {
    // 使用专用记忆提取模型 (如 Qwen2.5-3B)
    this.useMainModel = false;
    this.modelClient.updateConfig(config);
  } else {
    // 兜底：使用主对话模型
    this.useMainModel = true;
    const mainModelConfig = this.getMainModelConfig();
    this.modelClient.updateConfig(mainModelConfig);
  }
}
```

### 3. MemoryModelClient (LLM 提取层)

**文件**: `src/agent/memory/MemoryModelClient.ts`

**职责**: 调用 LLM 提取记忆，解析输出

**输出格式**:
```
[类型] 内容 | 重要性
```

**示例**:
```
[identity] 用户是一名软件工程师 | 0.9
[preference] 用户喜欢使用深色主题 | 0.8
[fact] 项目使用 React + TypeScript 技术栈 | 0.85
```

**MultiPassParser (三轮解析策略)**:

| Pass | 策略 | 正则 | 说明 |
|------|------|------|------|
| Pass 1 | 严格匹配 | `^\[(type)\]\s*(.+?)\s*\|\s*(0\.[7-9]\d*\|1\.0)\s*$` | 完整格式匹配 |
| Pass 2 | 宽松匹配 | 容忍格式偏差 | 处理轻微格式问题 |
| Pass 3 | 关键词提取 | 检测关键词 | 兜底策略 |

**SafeExtract (安全验证层)**:

```typescript
// 验证规则
- 类型白名单: identity, fact, preference, task, constraint, skill
- 内容长度: 10-200 字符
- 重要性范围: 0.7-1.0
- 垃圾字符检测: 重复字符、纯符号
- 完全字符串去重
```

### 4. SimilarityEngine (相似度决策层)

**文件**: `src/agent/memory/SimilarityEngine.ts`

**职责**: 基于向量相似度决定记忆的存储策略

**决策阈值**:

```typescript
interface SimilarityThresholds {
  duplicate: number;      // 0.85 - 判定为重复
  merge: number;          // 0.75 - 判定为合并
  minSimilarity: number;  // 0.3  - 最低相似度
  minScoreForCleanup: number; // 0.3 - 清理阈值
}
```

**决策流程**:

```
                    ┌─────────────────┐
                    │ 计算相似度       │
                    │ (cosine)        │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │ 类型过滤         │
                    │ 只比较同类型记忆  │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
              ▼              ▼              ▼
        similarity     similarity     similarity
          > 0.85       0.75~0.85        < 0.75
              │              │              │
              ▼              ▼              ▼
        ┌─────────┐    ┌─────────┐    ┌─────────┐
        │  SKIP   │    │  MERGE  │    │ INSERT  │
        │ 跳过    │    │ 合并    │    │ 新增    │
        │ +boost  │    │         │    │         │
        └─────────┘    └─────────┘    └─────────┘
```

**动态 topK 计算**:
```typescript
// 根据记忆总量动态调整搜索范围
const topK = Math.min(50, Math.max(10, Math.floor(totalMemories * 0.05)));
```

**保守合并策略**:
```typescript
// 只有包含关系才合并
if (existing.includes(newContent)) return existing;
if (newContent.includes(existing)) return newContent;
// 否则合并失败，fallback 到 insert
```

### 5. MemoryStore (存储层)

**文件**: `src/agent/memory/MemoryStore.ts`

**职责**: 执行存储决策，管理记忆生命周期

**并行 Embedding 生成**:
```typescript
// 使用 Promise.all 并行生成所有候选记忆的 embedding
await Promise.all(
  candidates.map(async (c) => {
    if (!c.embedding) {
      c.embedding = await this.config.generateEmbedding(c.content);
    }
  })
);
```

**存储结果**:
```typescript
interface StoreResult {
  accepted: MemoryItem[];  // 新增的记忆
  skipped: { content: string; reason: string }[];  // 跳过的记忆
  merged: { existing: MemoryItem; newContent: string }[];  // 合并的记忆
}
```

### 6. MemoryScoreCalculator (评分层)

**文件**: `src/agent/memory/MemoryScoreCalculator.ts`

**职责**: 计算记忆的综合评分，支持记忆衰减和访问奖励

**评分公式**:
```
score = importance × decay + access

其中:
  decay = 0.5^(ageInDays / halfLifeDays)
  halfLifeDays = 30 天
  access = min(accessCount × 0.01, 0.2)
```

**评分组成**:

| 组成部分 | 计算方式 | 说明 |
|----------|----------|------|
| base | importance | 基础重要性 |
| decay | 0.5^(天数/30) | 时间衰减因子 |
| access | min(次数×0.01, 0.2) | 访问奖励 |

**清理策略**:
```typescript
// 评分低于阈值的记忆可被清理
if (score.final < 0.3) {
  // 标记为待清理
}
```

## 记忆类型定义

```typescript
type MemoryType = 
  | 'identity'    // 身份信息 (如: 用户是软件工程师)
  | 'fact'        // 事实信息 (如: 用户在深圳工作)
  | 'preference'  // 偏好信息 (如: 用户喜欢深色主题)
```

**类型均衡策略**:

```typescript
const limits = {
```

## 双模型配置

### 专用记忆提取模型 (推荐)

```typescript
interface MemoryModelConfig {
  enabled: true;
  provider: 'lm-studio' | 'ollama';
  baseUrl: 'http://localhost:1234/v1';
  modelName: 'qwen2.5-3b-instruct';  // 推荐: 小型高效模型
  temperature: 0.2;                   // 低温度保证稳定输出
  maxTokens: 800;                     // 足够输出 8 条记忆
}
```

**推荐模型**:
- Qwen2.5-3B-Instruct (推荐)
- Qwen2.5-7B-Instruct
- 其他小型指令模型

### 主模型兜底模式

当专用模型不可用时（如老电脑、无显卡、使用在线 API），系统自动切换到主模型：

```typescript
// 自动从 localStorage 获取主模型配置
const mainModelConfig = {
  enabled: false,
  provider: 'lm-studio',
  baseUrl: localStorage.getItem('nexus_lm_studio_url'),
  modelName: localStorage.getItem('nexus_model_name'),
  temperature: 0.2,
  maxTokens: 800,
};
```

**兜底模式特点**:
- 仍然使用新的 Pipeline (PreFilter + SimilarityEngine + Embedding)
- 会消耗主模型的 token
- 日志会显示: `[MemoryExtraction] 使用主模型进行记忆提取 (兜底模式)`

## Embedding 模型

**当前使用**: `bge-small-zh-v1.5`

**特点**:
- 中文优化
- 向量维度: 384
- 适合语义相似度计算

**使用场景**:
1. 记忆去重 (相似度 > 0.85 → 跳过)
2. 记忆合并 (相似度 0.75~0.85 → 合并)
3. 记忆检索 (基于查询向量搜索相关记忆)

## 完整数据流

```
1. 用户发送消息
       │
       ▼
2. ReActEngine 处理对话
       │
       ▼
3. 触发记忆提取 (triggerMemoryExtraction)
       │
       ├── 检查触发条件 (消息数 ≥ 4 或 内容长度 ≥ 300)
       │
       ▼
4. MemoryExtractionService.triggerExtraction()
       │
       ├── 选择模型 (专用模型 or 主模型兜底)
       │
       ▼
5. PreFilterService.filter()
       │
       ├── 过滤短消息
       ├── 过滤工具调用
       ├── 角色过滤
       ├── 字符串去重
       └── 截取最近 N 条
       │
       ▼
6. MemoryModelClient.extractCandidates()
       │
       ├── 调用 LLM 提取记忆
       ├── MultiPassParser 解析输出
       └── SafeExtract 安全验证
       │
       ▼
7. MemoryStore.storeCandidates()
       │
       ├── 并行生成 Embedding (Promise.all)
       │
       ▼
8. SimilarityEngine.processCandidate()
       │
       ├── 搜索相似记忆 (动态 topK)
       ├── 类型过滤
       └── 计算相似度
       │
       ├──▶ 相似度 > 0.85 → SKIP + boost
       │
       ├──▶ 相似度 0.75~0.85 → MERGE
       │         │
       │         ├── 合并成功 → 更新记忆
       │         └── 合并失败 → fallback to INSERT
       │
       └──▶ 相似度 < 0.75 → INSERT
                │
                ▼
9. MemoryScoreCalculator.calculate()
       │
       ├── 计算 score = importance × decay + access
       └── 写入 memory.score
       │
       ▼
10. TauriMemoryClient.addMemory()
       │
       ▼
11. SQLite 数据库持久化
```

## 故障排查

### 问题 1: 记忆提取不触发

**检查项**:
1. 触发条件是否满足 (消息数 ≥ 4 或 内容长度 ≥ 300)
2. 是否有正在进行的提取任务 (`isExtracting = true`)
3. 模型配置是否正确

### 问题 2: 记忆提取失败

**检查项**:
1. 模型 API 是否可访问
2. 模型名称是否正确
3. 查看控制台日志中的错误信息

### 问题 3: Embedding 生成失败

**检查项**:
1. Rust 后端是否正确加载 Embedding 模型
2. 检查 `generate_embedding` 命令是否注册
3. 查看 Rust 后端日志

### 问题 4: 记忆重复存储

**检查项**:
1. 相似度阈值是否合理
2. 类型过滤是否生效
3. Embedding 模型是否正常工作
