# 记忆提取系统架构文档

## 概述

记忆提取系统是 Nexus AI Assistant 的核心组件，负责从对话中自动提取、去重、存储和检索与用户相关的长期信息。系统采用“规则 + 语义”驱动的架构，支持双模型配置（专用记忆提取模型 + 主对话模型），并具备完整的兜底策略与离线回归能力。

核心原则：
> 模型可以犯错，但 Filter 不能放错。
>
> 宁可错杀高比例，也不能放过一条 hallucination。

本次更新重点（2026-03-31）：
- 引入两阶段提取流程：Strict → Relaxed（严格优先，高精度兜底 → 放宽召回）
- 增加 MultiPassParser（JSON → 行解析 → 正则 → fallback）以提高解析鲁棒性
- 强化 SafeExtractor：置信度过滤、疑问句/二人称拒绝、Levenshtein 模糊去重
- 在模型提示中加入“低置信示例”，并将 relaxed 默认阈值调整为 `0.7`
- 新增离线回归与阈值 A/B 脚本：`scripts/memory_test_runner.ts` 与 `scripts/memory_ab_experiment.ts`
- 增加运行时 debug 导出（`log/memory_model_raw_outputs.json` 与 `log/memory_ab_experiment_results.json`）

## 核心组件详解（更新后）

### 1. MemoryExtractionService (主控制器)

文件: `src/agent/memory/MemoryExtractionService.ts`

职责：协调整个记忆提取流程、增量触发、并将单条用户消息按条调用模型以降低混淆与重复。

关键点（更新）：
- 仍保留增量触发（新消息数 / 新内容长度）机制；但在单条消息上按序调用 `MemoryModelClient.extractCandidates()`，以减少模型交互时的上下文干扰。
- 在提取链路中注入 debug 导出（原始 LM 输出、解析后候选、SafeExtractor 过滤日志）以便离线回归。

输入→输出流程核心（精简）:
- PreFilter → 对每条用户消息调用 `MemoryModelClient` → 收集 ParsedMemory 列表 → `filterMemories()` → 语义去重（embedding）→ 写入候选表

注：提取后会把候选记忆通过 `TauriMemoryClient.addCandidateMemory` 写入候选表，状态为 `pending`，等待人工或自动流转。

### 2. PreFilterService (预过滤层)

文件: `src/agent/memory/PreFilterService.ts`

职责：快速剔除不可提取内容，保证传给模型的输入尽可能干净。

主要配置（保留）：
- `userOnly: true`（只传用户消息）
- `skipToolCalls: true`（跳过工具调用消息）
- `minMessageLength`, `maxMessages`

说明：本次改动仍坚持只传用户消息到模型，减少 sourceText 来源混淆。

### 3. MemoryModelClient (LLM 提取层)

文件: `src/agent/memory/MemoryModelClient.ts`

职责：调用 LLM 提取候选记忆，解析模型输出，并运行两阶段的 SafeExtractor 校验。

重大改动（本次）：
- 两阶段提取：首先运行 **Strict** 提示（高 precision，minImportance ≈ 0.75），如无充足结果再运行 **Relaxed** 提示（更宽松以提高 recall）。
- Relaxed 提示中加入“低置信示例”（示例会要求模型为不确定片段输出较低的 `confidence` 值），并将 relaxed 的默认 `minImportance` 提升为 `0.7`（实验确定的折中值）。
- MultiPassParser：解析链路为 JSON parse → 行解析 → 正则解析 → 最后 fallback（减少格式抖动带来的失败率）。
- debugExtract：可导出每条消息的完整原始响应、解析候选、SafeExtractor 通过/拒绝详情，写入 `log/memory_model_raw_outputs.json` 用于离线分析。

输出格式（期望）：
```
[
  { "type":"identity|preference|constraint|fact", "span":"用户原话连续子串", "resolvedText":"语义抽象", "sourceText":"包含 span 的原句", "confidence":0.7 }
]
```

解析与校验（SafeExtractor 要点）：
- `minImportance`（严格/放宽）控制进入 Filter 的下限；Relaxed 默认 0.7
- 拒绝疑问句 / 第二人称导向（问题类内容不作为长期记忆）
- 垃圾字符与过短文本过滤
- Levenshtein / 相似度模糊去重：用于合并模型在措辞上产生的高相似度重复候选

注意：曾发生的模板字面反引号转义问题已修复（避免模板字面中未转义的反引号导致的构建错误）。

### 4. MultiPassParser（解析容错层）

职责：对模型输出进行稳健解析，优先尝试结构化解析，逐步回退以最大化解析成功率。

步骤：
1. JSON.parse — 若成功直接返回
2. 行解析 — 将输出按换行逐条 parse（常见格式）
3. 正则抽取 — 根据提示中预期字段名用正则抓取
4. Fallback — 去除思考标签、code fence、html 等，再次查找 JSON 区段

此策略显著降低了小模型输出格式抖动带来的丢失。

### 5. SafeExtractor（安全校验层）

职责：对 ParsedMemory 执行强规则验证与去噪，保证进入 Filter 层的候选质量。

关键规则（更新）：
- `minImportance`（Strict/Relaxed 可配置）
- `rejectInterrogative`: 拒绝疑问句与指向性的“你/你们”类输出
- `normalize()`: 标点/空白规范化 + 最小长度阈值
- `isSimilar()`：基于 Levenshtein 和长度权重的模糊相似度，用于抑制重复

通过 Strict→Relaxed 的组合，可以让系统在高精度场景下保持稳定，在需要更多召回时仍能可控放宽。

### 6. MemoryFilter（强规则过滤）

文件: `src/agent/memory/MemoryFilter.ts`

职责：进一步基于业务规则过滤不合格候选（类型校验、证据校验、questionFilter、短期事件剔除等）。

本次更新要点：
- 将默认置信度阈值逻辑对齐为：Strict 高阈（≈0.75），Relaxed 默认 0.7（由 A/B 实验验证）
- 加强 questionFilter（问句模式检测）并在 SafeExtractor 中尽早剔除
- 增强 fuzzyMatch 与 span 对齐策略（多策略前缀/后缀校正、核心词提取、跨句匹配）以容忍小模型对 span 的改写

### 7. MemoryStore / SimilarityEngine

职责：并行生成 embedding（通过 Tauri RPC 到后端 EmbeddingService），执行语义相似度计算并决定 INSERT / MERGE / SKIP 操作（阈值 0.75/0.85 等可配置）。

本次变更：
- 前端会在候选去重阶段调用 `TauriMemoryClient.generateEmbedding` 以获得候选与已有记忆的向量并完成语义去重/合并。

### 8. TauriMemoryClient 与 EmbeddingService（Rust 后端）

文件: `src/agent/memory/TauriMemoryClient.ts` 与 `src-tauri/src/memory/embedding.rs`

职责：前端通过 Tauri RPC 调用后端的 EmbeddingService 进行向量生成、模型管理（下载/初始化/校验）、并由后端负责向量检索与数据库操作。

实现要点（总结）：
- 默认 EmbeddingProvider 为 Local，默认 model_id 为 `BAAI/bge-small-zh-v1.5`（可在设置中选择其他模型）。
- 本地模型缓存目录为：`{系统缓存目录}/nexus-ai-assistant/embedding-models/{model_id.replace('/', '_')}`，因此 `BAAI/bge-large-zh-v1.5` 会映射为 `BAAI_bge-large-zh-v1.5`。
- EmbeddingService 支持同步与异步的模型下载、完整性校验、加载（`model.safetensors` 或 `pytorch_model.bin` + `config.json` + `tokenizer.json`）。

前端 Settings 页与命令：
- `get_embedding_provider` / `initialize_embedding_with_model` / `download_embedding_model` / `open_model_folder` 等接口已提供，用户可以在 UI 中下载并加载本地模型。

## 调试与离线回归工具（新增）

为便于对小模型（如 qwen2.5-3b-instruct）做稳定性回归，本次增加了以下脚本：

- `scripts/memory_test_runner.ts` — 对话集合逐条调用 `MemoryModelClient.debugExtract`，并将原始 LM 输出与解析流水写入 `log/memory_model_raw_outputs.json`。
- `scripts/memory_ab_experiment.ts` — 对上一步生成的原始输出做阈值网格搜索（例如 `[0.6,0.65,0.7,0.75]`），并将结果写入 `log/memory_ab_experiment_results.json`，用于选择 Relaxed 阈值。

运行示例：
```bash
# 生成原始 LM 输出（可多次运行以收集回归集）
npx tsx scripts/memory_test_runner.ts

# 在原始输出基础上做阈值 A/B 实验
npx tsx scripts/memory_ab_experiment.ts
```

产物示例：
- `log/memory_model_raw_outputs.json` — 每条消息的 strict/relaxed 原始响应、解析候选、safe 通过列表、合并结果
- `log/memory_ab_experiment_results.json` — 每个阈值的接受/拒绝统计与对比表

这些离线产物可直接加入 CI 回归套件，便于在 Prompt 或阈值调整后做回归比对。
